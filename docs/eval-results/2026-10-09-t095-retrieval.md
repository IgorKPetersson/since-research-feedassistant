# T-095 — Retrieval before and after, on the frozen dataset

2026-10-09. Frozen dataset (archive checked against `docs/eval-dataset-manifest.txt` on every
run), reference date 2026-09-17, `qwen3:30b-a3b`, `bge-m3`. The answer key
(`docs/eval-questions.md`) and the earlier graded results are unchanged.

**Before** is `v2-development` at `8fd743b`: retrieval and answer prompt as in
`v1-pre-improvement`. **After** is T-095: exact-name matching, a both-source quota, a
per-source pool, and the search-scope line (D-023).

## Method

- Expectations come from `docs/eval-expectations.json`. **v1** is the answer key as written,
  with each question's explicit date filter: the window the graded runs searched (the
  original parser at 2026-09-17). **v2** changes only F11, to the corrected "förra veckan"
  (Mon 2026-09-07 – Sun 2026-09-13, 146 papers in the frozen archive).
- Both code versions get the same explicit filter, ranking flag and source filter for every
  question. Date-parser changes (T-093–T-106) therefore can't show up as retrieval changes.
- Retrieval: `scripts/t095_retrieval_eval.py run`, which records the documents packed into
  the model's context. Answers: `scripts/t095_retrieval_eval.py answers`, graded by hand
  against the answer key's criteria. One answer per question and version; model sampling
  varies between runs, so a single grade change is weak evidence on its own.
- Raw results: `docs/eval-results/t095/`.

## Discrepancies in the original setup, recorded

- **F11.** The answer key's window is 2026-09-10 – 2026-09-16 (137 papers). The graded runs
  searched 2026-09-11 – 2026-09-17 (D-012's anchor), which holds 105 of them: the 32 papers
  dated 2026-09-10 were outside the filter. No paper is dated after 2026-09-16, so nothing
  outside the key's window could be found.
- **F15.** Expected source 2609.08149 (SWE-Bench Pro Verified) is dated 2026-09-10, outside
  the graded runs' filter 2026-09-11 – 2026-09-17. No run could have retrieved it.

What the gains can be attributed to:
- **F02** to retrieval: the "GUI" name match put all five key papers into the context.
- **F06 and F12** are answer changes with the expected source already in the context
  before. They may come from the scope line or from sampling; one run can't tell.
- The first after-run had two **regressions caused by T-095**: the exact-name counts in
  the prompt made the model answer about the typo "Copding" (F04) and repeat "Palantir in
  no source" (F12). The counts were removed from the prompt and kept in the app's lines;
  the second run has neither regression.

## Remaining limits

- **F14** still fails. Its key papers rank 324th and 893rd in a papers-only search for the
  Swedish question; BM25 fusion did not help (prototype, rejected in D-023). The quota now
  gives the answer papers, but the nearest ones aren't about open-source alternatives, and
  one expected video is pushed out. A semantic gap between Swedish questions and English
  abstracts, recorded in PLAN's risk register.
- **F04** fails under the key, as before. The key expects "nothing substantial about coding
  agents that week"; both versions report Claude Code and software-factory videos from the
  week, which the key doesn't count.
- **F15** can't reach SWE-Bench Pro Verified with the graded filter, and its other key papers
  rank too low for the context; it passes on equivalent agent papers.
- **Exact names** are found by shape. A typo ("Copding") is counted as a name with no
  matches, and a lower-case name isn't recognised. The counts are shown to the user only.
- **Channel coverage** in the scope can't be shown on the frozen set, which has no channel
  records. It is covered by unit tests and was checked in the running app with live data.
- One answer per question and version. Re-running would show how much of F06 and F12 is
  sampling.
