## 7. Needle test, model pair revision, embedding model  [T-006]
   - 7.1 Needle-in-haystack: secret planted at the very start, ~9796 real tokens
     - 7.1.1 Default num_ctx turned out to be 32768, not the model's trained max
     - 7.1.2 num_ctx above the real prompt size changes nothing about what's evaluated
     - 7.1.3 num_ctx=4096 (undersized): only 2050 tokens evaluated, secret silently lost,
       no error at all
       · outcome: **KB-005**, the session's most consequential finding
   - 7.2 Read Chroma's installed source: the "document too long" check in `_forward()` can
     never fire — the tokenizer already truncated to 256 tokens one line earlier
     · outcome: confirmed two ways (identical embeddings for a differing tail; `add()`
       accepts an overlong doc) — **KB-006**
   - 7.3 Researched Ollama's library (qwen3, gemma3) and bge-m3 via `curl` (WebFetch was
     blocked by a hook; curl worked) — presented real candidates before pulling anything
     · outcome: qwen3:8b + qwen3:30b-a3b chosen over Gemma3, with 3 conditions
   - 7.4 Pulled the pair + bge-m3; both 100% GPU simultaneously at num_ctx=16000, ~2.4GB
     headroom; bge-m3 correctly ranked a Swedish query against English candidates
     · outcome: **D-005**, supersedes D-003
   - 7.5 `think:false` does not suppress Qwen3's reasoning — it merges it into `response`
     instead of separating it into `thinking`
     · outcome: KB-007
   - 7.6 Framing: describe the pair by VRAM footprint (~6GB vs ~20GB),
     not "large vs small" — MoE model has fewer active params than the dense 8B
     · outcome: applied throughout D-005, KB-007, the project rules
